# AI面试帮手-面试克星 Spec

## 1. 项目信息
- 项目背景：专注于面试场景的 AI 应用，旨在通过 AI 评估功能以及模拟面试功能帮助求职者准备面试
- 技术栈：
前端Vite + React 19+ TypeScript+Tailwind+shadcn/ui
状态管理 Zustand
路由 React Router v6
后端Node.js + Express + TypeScript
数据库MongoDB
部署 Vercel
- 截止时间：2026年9月1日(最晚)

---

## 2. 功能需求
| 功能 | 说明 | 页面 |
|------|------|------|
| 用户登录 | 验证用户名密码，跳转到首页 | login.tsx |
| 用户注册 | 提交邮箱，密码和验证码，跳转到登录页 | register.tsx |
| 首页 | 显示学习进度，查看复盘以及基础题库 | Home.tsx |
| 个人主页 | 存放和修改个人信息和简历 | Profile.tsx |
| 练习页面 | 负责存放各个面试的入口以及收藏的面试题 | Practice.tsx |

## 7. 验收标准

### 用户系统
- [ ] 用户能通过邮箱和密码完成注册
- [ ] 用户能用已注册的邮箱和密码完成登录
- [ ] 登录成功后，页面能正确跳转至首页
- [ ] 登录状态能在不同页面间保持（刷新后仍为登录状态）

### 页面骨架
- [ ] 5 个页面（首页、登录、注册、个人主页、练习）都能通过 URL 访问
- [ ] 练习页面内部，能通过 Tab 或按钮在“基础题库”和“AI面试”两个子模块间切换

### 数据与接口
- [ ] `/api/register` 接口能正确创建新用户，并存入数据库
- [ ] `/api/login` 接口能正确校验用户密码，并返回 JWT

## 8. 开发计划

### MVP 1：用户系统 + 骨架
- [ ] 前端路由搭建（5 个页面能跳转）
- [ ] 后端 Express 项目初始化
- [ ] MongoDB 连接 + User Schema 定义
- [ ] `/api/register` 接口实现
- [ ] `/api/login` 接口实现（JWT）
- [ ] 前端登录/注册页面 + 接口联调
- [ ] 个人主页基础布局（展示用户名、年龄、性别、最高学历）

### MVP 2：基础题库 + 简历
- [ ] 题目数据模型设计（Question Schema）
- [ ] 种子数据准备（AI 生成或手动整理）
- [ ] `/api/questions` 接口实现
- [ ] 基础题库组件（选题、答题、看答案）
- [ ] 简历上传功能（文件解析 + AI 提取）
- [ ] 个人主页简历展示

### MVP 3：首页 + 进度
- [ ] 答题记录数据模型（Record Schema）
- [ ] 打卡功能（每日记录）
- [ ] 复盘功能（历史答题回顾）
- [ ] 首页仪表盘（进度、打卡、复盘入口）

### MVP 4：AI 面试
- [ ] AI 服务模块封装（DeepSeek API）
- [ ] Prompt 模板设计（出题 + 追问 + 评估）
- [ ] AI 面试组件（多轮对话）
- [ ] AI 评分与反馈展示
- [ ] JD 上传 + 结合简历生成个性化题目

## 9. 风险预案
| 风险 | 影响 | 应对方案 |
|------|------|----------|
| **React 学习曲线超过预期** | MVP 1 骨架搭建时间翻倍 | 只做核心页面，复杂交互留给后续 MVP；每天遇到问题立刻问本地模型或 DeepSeek，不卡着 |
| **DeepSeek API 调用失败或不稳定** | AI 面试功能无法上线 | MVP 4 阶段先用 mock 数据模拟 AI 响应，确认前后端链路通畅后再接入真实 API |
| **MongoDB Atlas 免费额度耗尽** | 数据库不可用 | 本地开发使用 MongoDB 本地服务；Atlas 512MB 对个人项目足够，正常使用不会超额 |
| **Vercel 部署不成功** | 项目无法上线 | MVP 1 阶段就尝试部署一次（哪怕只有一个页面），提前发现配置问题 |
| **数据库设计前期不完善，后期频繁修改 Schema** | 返工成本高 | 每个 MVP 开始前先在 Spec 里完善对应的 Schema 设计；每次修改 Schema 都记录在 Spec 里 |
